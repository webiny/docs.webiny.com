## Development

### Documented Constructor Dependency Safety in GraphQL Resolvers ([#6148](https://github.com/webiny/webiny-js/pull/6148))
> ⏳ REVIEW-PENDING `@adrians5j`: confirm this entry, then delete this line.

GraphQL schema factories receive their constructor dependencies from the request that builds the schema, which is cached for the life of the Lambda container. Reading constructor-injected dependencies (like `IdentityContext`) inside a resolver can expose stale data from the request that originally built the schema, potentially causing authorization issues in deployed environments. Documentation has been added to warn against this pattern — constructor dependencies should only be used in the `execute()` method, not inside resolvers.

### Updated Lexical Editor Dependencies ([#6169](https://github.com/webiny/webiny-js/pull/6169))
> ⏳ REVIEW-PENDING `@brunozoric`: confirm this entry, then delete this line.

Lexical packages have been updated from 0.52 to 0.53. This update includes breaking changes to Lexical's type system — methods like `getParent`, `getChildren`, `getNextSibling`, and `getPreviousSibling` no longer accept generic type arguments. If you have custom Lexical extensions, you may need to update your code to use type guards like `$isListNode` or `$isListItemNode` instead.

## Website Builder

### Fixed `getPageByPath` Not Returning Required Fields ([#6166](https://github.com/webiny/webiny-js/pull/6166))
> ⏳ REVIEW-PENDING `@adrians5j`: confirm this entry, then delete this line.

The `getPageByPath` resolver was missing `version`, `metadata`, and `extensions` fields, causing GraphQL errors when fetching published pages through the Website Builder SDK. This affected all frontend applications built on the SDK (Next.js, Nuxt, etc.), where every published page failed to load with `Cannot return null for non-nullable field WbPage.version`. The resolver now returns the complete set of fields required by the SDK.
