Source of Information:
1. Slack thread in #CUSPFP9TR (2026-09-22): 6.5 needs docs on setting up the SDK from the starter kit. Some users (Kibo and their clients) built on the 6.4 starter kit, which differs from 6.5. Others (MG) never used the SDK. Pavel asked for scenario-specific AI prompts, all in one place.
2. github.com/webiny/website-builder-nextjs, diff between `main` (6.4 kit) and `starter-kit-6.5.x` (6.5 kit)
3. webiny-js `release/6.5.0`: packages/sdk-nextjs, packages/sdk-frontend (FrontendSdk, WbSdk, CmsSdk, types), packages/cms-nextjs
4. webiny-js `release/6.5.0`: packages/api-website-builder/src/features/nextjs (NextjsConfig, NextjsConfigLegacyFallback), features/installer/ApiKeyInstaller.ts
5. webiny-js `release/6.5.0`: packages/frontend-settings (Configure Frontend dialog, Frontend Domain), app-headless-cms preview (resolvePreviewUrl, PreviewPane)

Key Documentation Decisions:
1. One page covers every scenario, as requested in the thread. The new-project case links to setup-nextjs.mdx instead of repeating it.
2. Each scenario leads with a copy-paste AI prompt, followed by manual steps that describe the same changes so readers can review the agent's work.
3. Prompts are self-contained. They include the full old-to-new API mapping so they work without web access, and they also point at the starter-kit-6.5.x branch as the reference.
4. The upgrade prompt tells the agent NOT to move files out of src/. The layout change is cosmetic, and moving files creates a large, risky diff for client sites.
5. The prompts warn against renaming component `name` values, because published pages store them.
6. "Existing Frontends Keep Working" section addresses the Kibo case: Kibo hosts the Webiny API, and its clients host their frontends. Pavel stated the GraphQL API is unchanged, so 6.4 SDK packages keep working. Sven planned to verify this against webiny.com. Re-check before publishing if that hasn't been confirmed.
7. Code blocks for prompts use ```text.

Understanding the 6.4 to 6.5 SDK change:
- Packages: @webiny/website-builder-nextjs + @webiny/sdk -> @webiny/sdk-nextjs (re-exports @webiny/sdk-frontend, @webiny/cms-nextjs, @webiny/website-builder-nextjs)
- `sdk` singleton (FrontendSdk): sdk.init(config), sdk.wb, sdk.cms, sdk.languages, sdk.fileManager, sdk.tenantManager, sdk.tasks, sdk.webhooks, sdk.isEditing()
- ContentSdkConfig: { endpoint, token, tenant?, preview?, fetch?, cms?, wb?: { theme?, previewParams?, componentGroups? } }
- sdk.wb.getPage / listPages / getRedirectByPath / getAllRedirects return Result. getPage also resolves content-entry inputs.
- createWbComponent === createComponent (both re-export website-builder-sdk createComponent). createCmsComponent is the CMS live preview equivalent.
- Webpack helper: @webiny/sdk-nextjs/webpack.js. Lexical CSS: @webiny/sdk-nextjs/lexical.css
- Env vars: NEXT_PUBLIC_WEBSITE_BUILDER_* -> NEXT_PUBLIC_WEBINY_*
- API key: new installs create "Frontend Integration" (slug frontend-integration) with wb.* read, cms content model/group/entry read, cms.endpoint.read, languages read. Upgraded projects keep "Website Builder" (slug website-builder). NextjsConfigLegacyFallback shows the legacy key and legacy env names when the new key is missing.
- Configure Frontend dialog: Dev Tools menu (was Support > Configure Next.js). It has a Frontend Domain field (shared by Website Builder and CMS live preview, falls back to the old WB previewDomain setting) and tabs per starter kit (Next.js, Nuxt).
- The 6.5 kit's package.json does not list @webiny/sdk-nextjs. Readers install it explicitly with a version matching their project.
- CMS live preview: model `.settings({ previewPath: "/articles/{values.slug}" })`. The Admin iframe loads `<domain><static prefix of previewPath>/preview?wb.editing=true&wb.type=entry&wb.id=<id>&wb.path=...`.
